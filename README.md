# 원격제어 v1.9.12

## v1.9.12 FHD 미만 해상도 차단

원격에서 고르는 화면 크기는 1920×1080(FHD) 이상만 허용합니다. 웹 뷰어와 설정 창의 목록에서 1600×900, 1366×768, 1024×768 등 FHD보다 작은 크기를 빼고, 서버도 그런 요청을 거부하며 이유를 알려 줍니다. 이전 판에서 FHD보다 작게 저장된 값은 모니터 없는 PC에서도 다시 적용하지 않습니다.

참고: 192.168.195.141에서 화면이 25초마다 1024×768로 떨어지던 현상은 원격제어가 아니라 **DisplayPort 모니터 접촉 불량**이었습니다. 원격제어·GAVI·가상 모니터를 각각 멈춰도 계속됐고, 모니터가 1.4초씩 인식되지 않는 모습이었습니다. [조사 기록](docs/session-display-1911.md#4-v1912-fhd-미만-해상도-차단과-25초-주기-깜빡임).

## v1.9.11 세션 전환 재로그인·해상도 깜빡임·첫 영상 연결 수정

- **RDP로 쓰던 PC에서 Windows 로그인 후 끊김:** Windows가 사용자 세션을 콘솔로 옮기면 대리 프로세스가 새로 뜨는데, 화면 로그인이 메모리에만 있어 다시 로그인해야 했습니다. 이제 SYSTEM·관리자만 읽는 폴더에 토큰 해시로만 암호화해 두어, 몇 초 뒤 자동으로 이어집니다. 로그인이 정말 만료되면 뷰어가 로그인 화면으로 갑니다.
- **4K 적용 후 FHD ↔ 4K 깜빡임:** 저장된 해상도를 5초마다 강제해 전체 화면 프로그램과 다투던 것을 고쳤습니다. 모니터(또는 가상 모니터)가 있는 PC에서는 원격 요청을 그 자리에서만 적용하고, 계속 지키는 것은 모니터 없는 PC뿐입니다.
- **첫 접속이 GPU 영상 대신 JPEG(`DD`)로 남음:** 처음 영상을 쓸 때 helper 준비가 느린 PC에서 12초 걸려 브라우저 시한을 넘겼습니다. 대리 프로세스가 뜰 때 미리 준비합니다.

[원인·기록·확인 방법](docs/session-display-1911.md).

## v1.9.10 화면 전송 지연 개선

같은 LAN의 1440p 화면이 끊기고 늦고 흐리던 문제를 끝에서 끝까지 재고 고쳤습니다.

- **JPEG 화면:** 대리 프로세스의 타이머가 15.6ms 단위라 화면 전송 루프가 30fps 근처에 묶였습니다. 화면 연결 중에만 1ms로 올립니다. 1440p 스크롤은 25→34fps(p95 63→35ms), 영상 창은 48→60fps(p95 39→20ms)로 좋아졌습니다(유선 수준 회선 기준).
- **GPU 영상(H.264):** 1440p를 1080p와 같은 2→6Mbps로 보내며 8초마다 인코더를 다시 띄워 최대 0.7초씩 멎던 것을 고쳤습니다. 같은 LAN이면 처음부터 1440p 12Mbps(1080p 8, 4K 16)로 보냅니다. 첫 40초 정지 3번 → 0번, 지연 p95 218→88ms입니다.
- **LAN 방화벽:** GPU 영상 helper의 UDP 수신 규칙이 없어 다른 PC에서 영상이 붙지 못하고 JPEG로 돌아갈 수 있었습니다. helper 파일 하나에만 사설·도메인 망 UDP를 허용합니다.

**확인 필요:** 업데이트 뒤 다른 LAN PC에서 접속해 뷰어 상단 `캡처` 칸이 `h264_…`로 바뀌는지 확인하세요. NVIDIA GPU만 있는 PC는 드라이버 610 이상이어야 GPU 인코딩이 됩니다(미만이면 JPEG). [측정·원인·한계](docs/stream-latency-1910.md).

## v1.9.7 Web MCP 통합 및 즉시 자동 시작

MCP 연결은 HTTPS/OAuth를 사용하는 Web MCP로 통일했습니다. 이전 직접 LAN 접속·stdio 연결기·MCPB 패키지와 내부 포트/허용 IP 입력 화면은 제거했습니다. 내부망에서도 LAN HTTPS 연결을 사용합니다. 저장된 Web MCP 사용 설정에 따라 화면 초기화 전에 내부 처리 서버를 시작합니다. 화면 포트 충돌이 MCP 시작을 막지 않으며, MCP 포트 충돌은 자동 재시도합니다. 기존에 설정된 웹 MCP 중계 작업과 HTTPS 서비스를 바로 확인하고 중지 상태이면 실행합니다. 초기 터널 연결의 5초 고정 대기를 제거했습니다. 인증·주소·사용 안 함 설정은 유지합니다. [동작과 검증](docs/mcp-startup-197.md).

## v1.9.6 100MB 초과 웹 업로드 개선

파일 크기가 8MiB를 초과하면 2MiB씩 분할하여 전송합니다. 프록시의 단일 요청 100MB 제한 및 업로드 연결 중단에 대응하고, 조각별 SHA-256 검증·서버 확인 위치부터 재개·동일 파일명 보존·전송 취소를 지원합니다. 완료 시 전체 파일 SHA-256을 계산합니다. 하위 PC 중계도 분할 전송을 전달하며 읽기 유휴 제한을 120초로 연장했습니다. 하위 PC로 업로드하려면 해당 PC도 새 버전이 필요합니다.

격리된 실제 HTTP 서버로 130MiB 파일 업로드와 복구·변조·취소 18개 검사가 통과했습니다. 운영 외부 터널·Edge 실기 검사는 별도로 확인해야 합니다. [상세 동작·검증](docs/large-upload-196.md).

## v1.9.5 원격 웹 프라이버시 화면 (실기 테스트 필요)

웹 원격제어 화면 상단에 **◼ 모니터 가리기 / ◻ 화면 복구** 버튼이 추가되었습니다. 물리 PC 모니터만 검정색으로 가리는 창을 띄우고 Windows 캡처 제외 기능으로 웹 원격 화면을 유지합니다. 화면 전원은 끄지 않습니다. 연결 종료·서비스 종료 시 자동 복구, PC 키보드 **Ctrl+Alt+Shift+F12**로 긴급 해제, 다중 모니터 지원, 타 세션에서 소유권 탈취 방지 및 로그인된 다른 세션의 해제를 지원합니다.

**주의:** 이 기능은 Windows 10 2004 이상에서 지원됩니다. 그래픽/캡처 드라이버에 따라 원격 화면에 가림창이 보일 수 있으므로 실제 PC에서 화면 가림 및 원격 영상 유지 여부를 확인해야 합니다. 보안 데스크톱(UAC, 잠금 화면)에는 가림창이 보이지 않을 수 있습니다. [사용 방법·한계·테스트](docs/privacy-screen-195.md).

## v1.9.4 PC 부팅 텔레그램 접속 알림

Windows 서비스가 PC 부팅 후 시작되면, 화면 터널의 공개 접속이 확인된 시점에 텔레그램으로 PC 이름, 원격제어 계정, 터널 서버·계정·장비명, 현재 화면 주소 및 MCP 주소를 전송합니다. 같은 부팅 중 서비스/터널이 재시작해도 중복 전송하지 않고, 주소가 변경됐다면 이전 주소도 함께 표시합니다.

2분 내 터널이 확인되지 않으면 연결 대기 상태를 알리며, 이후 터널이 준비되면 정상 주소를 추가 전송합니다. 전송 실패는 재시도하고 텔레그램 알림을 꺼 둔 PC에는 보내지 않습니다. `bench\Test-StartupNotify.ps1`로 실제 텔레그램을 호출하지 않고 검증할 수 있습니다.

## v1.9.2 MCP 작업공간 안내 수정

작업폴더는 기본 작업 위치입니다. 파일·폴더 전송·프로그램 실행과 명시적 `cwd`는 작업공간 밖의 로컬 경로도 사용할 수 있으며 실제 접근은 원격 실행 계정의 Windows 권한을 따릅니다. UI·도구 설명·LAN/웹 MCP 안내에서 이를 명시하고, 상태 응답의 `allowed_roots`를 `workspace_directories`와 `workspaces_restrict_access:false`로 바꿨습니다. 실제 접근 거부와 파일 없음·경로 오류·비활성 기능도 구분합니다. 기존 폴더 설정값은 보존합니다.

업데이트 설치 후 MCP 연결을 다시 연결해 새 도구 설명과 초기 안내를 받으세요. [작업공간·접근 동작](docs/mcp-lan.md).


## v1.9.1 보안 설정 보호

- 인증·MCP·터널 등 PC 전체 설정은 관리자 권한으로만 변경합니다. 일반 트레이의 [관리자 설정]에서 UAC 인증 후 수정합니다.
- 창 위치는 사용자별 `LocalAppData/RemoteControl/ui-settings.txt`에 저장하며 서비스가 이 파일을 읽지 않습니다.
- 설치·업데이트·서비스 시작 시 기존 공용 폴더 및 설정/백업 파일의 일반 사용자 쓰기 권한을 회수합니다. 이관 실패 시 오류를 표시하고 비밀번호를 초기화하지 않습니다.
- Telegram DPAPI 파일은 SYSTEM/관리자만 읽을 수 있습니다. 트레이의 주소 전송은 고정 동작만 허용하는 로컬 IPC를 통해 서비스에 요청합니다.
- OAuth 압축 본문 거부 및 웹 의존성 갱신, Go 1.27.3으로 모든 Windows helper 재빌드.
- 검증과 적용 범위: [보안 수정 결과](docs/security-remediation-20261031.md).

## v1.9.0 GPU 영상 전송과 JPEG 개선

브라우저가 지원하면 GPU H.264 + WebRTC 영상으로 전환합니다. 첫 화면 표시를 확인한 뒤 전환하며 연결 실패·영상 정지 시 JPEG로 자동 복귀합니다. JPEG의 화면 이동 영역 누락, 과도하게 작은 타일, 오래된 타일 디코딩 대기도 개선했습니다.

AMD GPU와 Chrome에서 1080p·4K 암호화 영상 전송, 전송률 변경, 자동 복귀를 합성 화면으로 검증했습니다. 외부 UDP 연결이 차단되면 기존 터널의 JPEG를 사용합니다. [변경·측정 조건·설정](docs/video-performance-190.md).


## v1.8.22 Inno Setup 및 텔레그램 토큰 입력

`dist\RemoteControl_Setup.exe`는 Inno Setup 마법사입니다. 설치 경로·화면 포트·자동 실행·방화벽·가상 모니터를 선택하고, 선택 사항인 **텔레그램 알림** 단계에서 봇 토큰과 chat_id를 입력할 수 있습니다. 비워 두면 기존 값이 유지됩니다. 웹/LAN MCP 설정은 설치 완료 화면 또는 본체의 **Web MCP 설정**에서 열 수 있습니다.

공개 설치 파일에는 실제 봇 토큰이 없습니다. 입력한 토큰은 대상 PC의 DPAPI 저장소에 암호화하며 명령줄·설치 로그에 넣지 않습니다. 기존 설치 엔진과 제거 등록을 유지하여 중복 프로그램 항목을 만들지 않습니다. [설치·개인용 토큰 이전 안내](docs/setup-1822.md).

## v1.8.18 LAN WebMCP 다중 IP·연결 설정 복사

**Web MCP 설정 → LAN / 내부망 설정**에서 랜카드별 IPv4를 확인하고 기본·추가 접속 IP를 등록합니다. 적용 후 사용할 IP를 선택하면 Claude Code 명령, VS Code JSON, Cursor JSON, Codex 명령·TOML을 복사할 수 있습니다. 전체 연결 안내에는 MCP·인증 주소, 공개 CA 다운로드 주소와 실제 CA 파일의 SHA256을 포함합니다.

각 IP는 자신의 HTTPS/OAuth 주소로 연결되며, 기존 주소의 인증 상태와 공개 CA는 유지됩니다. [설정·CA 등록·클라이언트 예제](docs/webmcp-lan-offline.md).

## v1.8.14 WebMCP 파일·폴더 전송

로컬·외부 LLM은 같은 HTTPS `/mcp` 주소를 사용합니다. LLM PC에 별도 연결기를 설치하지 않습니다. **Web MCP 설정 → Web MCP 주소 복사**로 등록 주소를 복사하고 기존 Remote ID/PW로 로그인합니다.

`pc_open_file_transfer`가 발급한 일회용 링크를 열면 브라우저에서 파일·폴더를 선택해 보내거나 원격 파일·폴더 ZIP을 받습니다. 직접 MCP 바이너리 전송도 256KiB 분할 전송과 SHA-256 검증을 지원합니다. 중단된 업로드는 전송 ID·원본을 보존해 24시간 안에 재개할 수 있습니다. 파일 최대 4GiB, 폴더 합계 8GiB, 항목 10000개입니다. [전송 사용법](docs/webmcp-file-transfer.md).

## v1.8.12 MCP 인증 유지

MCP 인증은 원격제어·웹 중계 재시작과 일시적인 통신 장애 뒤에도 유지됩니다. 로그아웃, 앱 연결 해제 또는 원격제어 ID·비밀번호 변경 시 해제됩니다. 화면용 브라우저 로그인은 기존 8시간 정책을 유지합니다. 이전 버전의 메모리 인증은 이전할 수 없어 업데이트 후 처음 한 번 다시 로그인해야 합니다.

인증 상태는 localhost 내부 처리기에서 Windows DPAPI, 웹 중계에서 AES-256-GCM으로 암호화합니다. 비밀번호는 저장하지 않습니다. access token은 1시간, refresh token은 회전하며 지속 인증합니다. 임시 통신 실패는 인증 해제로 취급하지 않고, 실행 명령은 자동 재전송하지 않습니다.

프라이빗 터널의 DNS·HTTPS 443·인증서 실패 때 살아 있는 SSH 연결과 발급 주소를 보존하고 원인을 표시합니다. 실제 SSH 연결이 종료되면 자동 재연결합니다. SSHTunnel 서버의 주소 길이 정책은 서버가 결정하며 클라이언트는 고정 길이를 요구하지 않습니다.

프라이빗 터널은 SSHTunnel 1.3 웹 API를 사용해 `https://랜덤키.터널도메인` 주소를 자동 발급받습니다. **외부망 → 연결 설정**에서 서버 주소·SSH 포트·계정·인증키·서버 지문을 입력하세요. [SSHTunnel 설정·사용법](docs/private-tunnel.md)을 참조하세요.

내부망은 **Web MCP 설정 → 내부망 HTTPS 설정**에서 연결합니다. 로컬 MCP 클라이언트는 공개 CA를 등록하고 HTTPS `/mcp` 주소와 OAuth 로그인을 사용합니다. [Web MCP 사용법](docs/webmcp.md)을 참조하세요.

4K 화면의 타일 준비·JPEG 압축·브라우저 디코딩과 전송 대기를 개선했습니다. 빠른 연결에서는 큰 타일과 전송 묶음을 사용하고, 수신이 밀리면 작은 타일로 돌아갑니다. 해상도는 유지합니다. 측정 조건과 한계는 [4K 성능 기록](docs/4k-performance.md)을 참조하세요.

프로젝트 폴더는 **현재 저장소의 루트**입니다. 안쪽에 같은 이름의 프로젝트 폴더를 만들지 않습니다.

## 빌드와 설치 파일

배포 결과는 항상 **프로젝트 루트의 `dist`** 한 곳에 생성합니다.

| 파일 | 용도 |
|---|---|
| `dist\RemoteControl.exe` | 프로그램 본체 |
| `dist\RemoteControl_Setup.exe` | 공유할 PC 설치·업데이트용 setup |
| `dist\RemoteControl_WebPlugin.zip` | HTTPS/OAuth MCP 연결 플러그인 |

프로젝트 폴더에서 아래 명령 하나로 본체와 setup을 함께 갱신합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\빌드_setup.ps1
```

본체만 만들 때는 `빌드.ps1`을 사용합니다. setup 빌드는 항상 현재 소스를 먼저 빌드한 뒤 그 본체를 포함하며, 본체와 setup의 버전이 다르면 실패합니다. 어느 폴더에서 스크립트를 실행해도 출력은 프로젝트의 `dist`로 고정합니다.

기본 setup에는 Tailscale 인증 키·chat_id·봇 토큰을 넣지 않습니다. 기존 Tailscale 키와 chat_id를 포함할 때만 `-IncludeTailscaleKey`를 명시합니다. 봇 토큰은 이 옵션으로도 포함하지 않습니다. `-NoKey`는 이전 명령 호환용이며 기본 동작과 같습니다. 빌드에는 Inno Setup 6이 필요합니다.

빌드는 설치된 서비스를 중지하지 않으며 관리자 권한도 요구하지 않습니다. `dist`의 파일을 직접 실행 중이어서 덮어쓸 수 없으면 그 실행본을 종료한 뒤 다시 빌드하세요.

실제 업데이트는 **`dist\RemoteControl_Setup.exe`**를 실행해 진행합니다. 설치 시 관리자 권한을 요청하고 원격제어 프로그램·서비스를 다시 시작합니다. 빌드만으로 `C:\Program Files\RemoteControl`의 설치본이 업데이트되지는 않습니다. 기존 프로그램이 떠 있으면 새 exe를 실행해도 중복 실행 방지 때문에 기존 창이 열릴 수 있습니다.
