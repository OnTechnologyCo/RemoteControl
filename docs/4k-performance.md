# 4K 화면 처리 개선 — v1.6.3

같은 4K 화면에서 다른 원격 프로그램보다 버벅인다는 보고를 따라 전송·타일 준비·브라우저 디코딩을 각각 측정했다. FPS를 낮추거나 해상도를 축소하지 않고 구현의 병목을 수정했다.

## 측정 (2026-09-29)

Ryzen 5 5625U, 3840×2160의 선이 많은 합성 화면, JPEG 품질 70. 실제 데스크톱이나 입력은 건드리지 않았다. 초기 합성 화면 생성과 JIT를 제외한 30회 평균이다.

| 단계 | 기존 | 수정 후 |
|---|---:|---:|
| 전체 지문 + 타일 준비 + JPEG | 569.8ms | 36.8ms |
| JPEG 디코딩 + Canvas 그리기 (Headless Edge) | 488.8ms | 42.3ms |
| 4K 전체 갱신의 JPEG 개수 | 510 | 12 |
| 전체 JPEG 전송량 | 2,483KiB | 2,174KiB |

준비 단계는 반복 DrawImage 자르기를 없앴을 때 113.1ms, 1024 타일을 사용했을 때 72.0ms, 큰 변경을 최대 4개 작업으로 압축했을 때 36.8ms였다. 단일 타일의 압축 시간만 보고 전체 4K 비용을 판단하면 안 된다. 모든 타일의 디코딩된 픽셀을 별도로 복사·압축한 기준 그림과 대조해 일치함을 확인했다.

별도 TCP/WebSocket 전송 시험은 510개 × 2KiB 모의 타일과 2ms ACK 지연을 사용했다. 실제 캡처·JPEG·브라우저는 포함하지 않는다.

| 전송 지표 | 기존 고정 묶음 | 자동 크기 + 송신 대기 분리 |
|---|---:|---:|
| 전달량 | 910KiB/s | 약 47,000KiB/s |
| 동일 타일의 재갱신 간격 p95 | 1,154ms | 32ms |

최신 타일로 교체하면 타일 자체의 캡처 시각은 최신이어도 같은 위치를 다시 보여 주는 간격은 1초가 넘을 수 있었다. 타일의 나이와 갱신 간격을 함께 봐야 한다.

**위 수치는 실제 4K 원격 접속에서 클릭부터 모니터 표시까지 잰 지연이나 60FPS 달성 결과가 아니다.** 복잡한 전체 화면 변화가 계속되면 캡처·인코딩·브라우저가 여전히 한계가 될 수 있다. 각 단계를 합성 부하로 분리해 비교한 결과이며 네트워크 실효 속도나 상용 원격 프로그램과의 비교 수치도 아니다.

## 적용 방식

- 디코딩 ACK가 빠르고 전송 묶음이 충분히 차면 16KiB에서 시작해 최대 512KiB까지 늘린다. 추가 대기가 커지면 최소 8KiB까지 줄인다. 미확인 묶음은 최대 2개다. 단일 JPEG가 더 크면 분할하지 않고 보낸다.
- 새 뷰어는 작은 왕복 메시지에 응답해 기본 RTT를 알려 준다. 거리가 먼 빠른 회선을 RTT만으로 제한하지 않는다. 구버전 뷰어도 기존 ACK 방식으로 연결된다.
- 새 뷰어가 큰 타일을 지원하고 4K 이상이며 충분한 전송 여유가 확인되면 1024 타일을 사용한다. 수신이 밀리면 128로 돌아간다. 해상도·화면 배율은 바꾸지 않는다.
- 타일 크기 전환은 별도 메시지로 좌표계와 세대 번호를 함께 바꾼다. 보이던 그림은 유지하며 이전 세대의 JPEG 완료가 새 타일을 덮지 못하게 한다. 마우스의 이전 좌표계 입력도 거른다.
- 캡처는 기존 16ms 간격을 유지한다. 남은 화면 전송은 ACK가 오면 즉시 재개한다. 준비된 화면을 매번 다시 압축해 전송이 굶지 않게 하되, 작은 묶음에서는 바로 최신 화면으로 교체하고 큰 묶음도 100ms가 지나면 새로 준비한다.
- 큰 변경만 압축을 나눈다. 작업마다 Bitmap·JPEG 파라미터·스트림을 따로 소유하며 원본은 읽기 전용으로 잠근다. 가장자리 타일은 실제 폭·높이만 인코딩한다.
- `갱신/s`는 화면 타일을 그린 브라우저 갱신 주기 수다. 정지 화면에서는 0이며 전체 화면의 완성 횟수가 아니다. 패킷이나 커서 이미지 수를 FPS로 표시하지 않는다.

느린 회선에서는 작은 묶음이 지연을 낮추는 대신 전달량이 줄 수 있다. 갑자기 회선이 느려지면 이미 보낸 묶음은 취소할 수 없으며 ACK 이후 다음 묶음부터 줄어든다.

## 재현

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File bench\Test-Control.ps1
node bench\ViewerControlTest.js
node bench\ViewerLint.js
powershell -NoProfile -ExecutionPolicy Bypass -File bench\Test-StreamServer.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File bench\Test-FrameTransport.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File bench\Test-4K.ps1 -TileSize 1024
.\빌드_setup.ps1
```

4K 서버 시험은 실제 StreamLoop와 JPEG를 사용해 큰 타일 전환, 12개 전체 도착, 느린 ACK 뒤 510개 타일로 복귀, 연결 종료를 검사한다. Edge 시험은 격리된 임시 프로필을 사용하고 실제 원격 PC에 연결하지 않는다. 출력과 시험 파일은 `artifacts/frame-transport`에 둔다.

배포 파일은 `dist/RemoteControl.exe`, `dist/RemoteControl_Setup.exe`로 고정한다. 빌드는 실행 중인 서비스를 바꾸지 않는다. 실제 화면을 보내는 PC에 설치하고 브라우저를 새로고침해야 전체 개선이 적용된다.
