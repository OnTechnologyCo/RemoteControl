# 터널 주소 유지와 텔레그램 알림 (v1.8.17)

## 변경 원인과 적용 조건

SSHTunnel 서버만 업데이트해도 구형 원격제어 EXE에 내장된 연결 helper는 바뀌지 않습니다. 이전 SDK는 연결할 때마다 새 터널키를 만들었으므로 SSH 연결이나 helper가 재시작하면 새 주소가 발급됐습니다.

SSHTunnel 1.5.0 SDK는 식별키를 저장합니다. 기본 서비스 식별자는 대상 포트이므로 매번 임시 포트를 만드는 MCP 프록시에서는 별도의 고정 식별자가 필요합니다. 원격제어 1.8.16부터 `Identity: "remotecontrol"`을 지정하며 1.8.17에도 이 수정을 포함합니다. 빌드 시 형제 폴더의 SSHTunnel 1.5.0 이상을 요구하고 helper를 다시 빌드해 본체에 포함합니다.

정상 SSH 재연결, helper 재시작, 로컬 포트·장비 표시 이름 변경은 저장된 식별키와 주소를 재사용합니다. 공개 DNS·인증서·443 연결 실패만으로 살아 있는 SSH 터널을 반복 폐기하지 않습니다.

주소 유지는 클라이언트 식별키와 서버의 주소 예약 데이터가 모두 보존되어야 합니다. 식별키는 실행 계정의 `AppData\Roaming\OnTech\SSHTunnel\identities`에 저장됩니다. SYSTEM 서비스와 일반 사용자 직접 실행은 서로 다른 프로필을 쓰므로 실행 계정을 바꾸면 다른 키를 사용할 수 있습니다. 서버 지문·터널 계정 변경, 저장 데이터 삭제, 관리자의 주소 재발급은 주소 변경 원인이 될 수 있습니다. 구형 클라이언트에서 처음 전환하면 주소가 한 번 변경될 수 있습니다.

## 알림 내용

주소 변경·연결 복구·장애·접속 주소 보내기와 자동 MCP 알림에 다음 정보를 표시합니다.

- Windows PC 이름
- 원격제어 로그인 ID
- 연결 방식
- SSHTunnel의 장비 표시 이름, 터널 계정, 서버와 SSH 포트
- 화면 주소 변경 시 이전 주소와 변경 주소
- 같은 텔레그램 수신자에게 이미 알린 MCP 주소가 바뀌면 이전 MCP 주소와 새 MCP 주소

실행 계정 SYSTEM을 원격제어 로그인 ID로 표시하지 않습니다. 비밀번호, 비밀번호 해시, 인증키, 텔레그램 봇 토큰을 알림의 계정 정보로 포함하지 않습니다. Tailscale 모드에서는 저장되어 있는 이전 SSH 계정을 표시하지 않습니다.

기존 공개 접속 확인, 중복 방지, 전송 실패 시 재시도 정책을 유지합니다. 알림 미리보기는 꺼진 상태로 전송합니다.

## PC 부팅 첫 알림 (v1.9.4)

서비스 자동 시작 후 터널의 공개 주소 접속 검사가 성공하면 현재 화면 원격제어 URL, MCP URL 및 준비 상태, PC 이름, 원격제어 로그인 ID, 터널 장비명·계정·서버/포트를 포함해 텔레그램으로 전송합니다. 부팅 중 화면 주소가 바뀌면 이전 주소도 함께 표시하며, 별도 주소 변경 알림은 중복 전송하지 않습니다.

Windows 부팅 시각과 Telegram 수신자 기준으로 성공 이력을 보존하므로 서비스와 대리 프로세스가 같은 부팅에서 재시작해도 재전송하지 않습니다. 약 120초 동안 공개 접속이 확인되지 않으면 현재 상태를 연결 대기 메시지로 보내고, 이후 접속 확인 시 최종 주소를 전송합니다. 텔레그램이 실패하거나 알림이 꺼진 경우 완료로 기록하지 않습니다. 실제 Windows 설정·토큰을 외부 테스트에 복사하지 않습니다.
