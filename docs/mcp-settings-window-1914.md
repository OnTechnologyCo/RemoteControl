# Web MCP 설정 중복 창과 아이콘 문자 — v1.9.14

## 원인

일반 권한 메인 창의 Web MCP 링크가 RequireAdminSettings를 호출했다.
이 함수는 --admin-ui로 메인 창을 하나 더 실행한 뒤 원래 클릭 처리를 끝냈다.
관리자 경로는 일반 UI의 중복 실행 mutex를 거치지 않아 반복 실행할 수도 있었다.
따라서 설정을 누른 사용자는 Web MCP 설정 대신 또 다른 메인 창을 보게 됐다.

또한 --admin-ui는 Application.SetCompatibleTextRenderingDefault(false)를 호출하지 않았다.
일반 UI와 관리자 UI가 서로 다른 Label/CheckBox 텍스트 렌더러를 사용하면서
모니터 모양 문자·상태 점 같은 글꼴 대체가 필요한 기호의 표시가 달라졌다.
실행 파일의 ICO 리소스가 손상됐다는 증거는 없다.

## 변경

- OpenMcpSettings는 일반 사용자에게 --mcp-settings 권한 상승을 요청한다.
  이 진입점은 McpForm만 만들며 MainForm·서버·트레이를 추가 생성하지 않는다.
  이미 관리자인 창에서는 소유자 모달 설정을 열어 기존 로컬 MCP 상태도 유지한다.
- 관리자 권한 검사는 별도 설정 진입점에서도 먼저 수행한다.
  일반 사용자 UI에서 보호된 설정을 직접 수정하도록 권한을 낮추지 않는다.
- SettingsWindow는 설정 종류별 세션 mutex와 활성화 event로 중복 창을 막는다.
  반복 클릭은 기존 창을 보이게 하고 활성화한다. 창을 닫으면 핸들과 타이머를 정리한다.
  이벤트는 창 활성화만 수행하며 설정값·경로·자격 증명을 전달하지 않는다.
- 일반 UI, 관리자 UI, 전용 MCP UI는 같은 DPI/VisualStyles/GDI 텍스트 초기화를 사용한다.
- McpForm은 내장 앱 아이콘을 표시하고 폼 종료 때 자신의 아이콘을 해제한다.
- 설정용 별도 관리자 프로세스와 서비스/대리 프로세스는 정상적으로 존재할 수 있다.
  이번 수정은 Web MCP 클릭으로 메인 창이 추가 생성되는 동작을 제거한다.
- Setup 파일명은 RemoteControl_Setup_v1.9.14.exe다.
  빌드 증빙은 보관 중인 과거 버전 Setup을 현재 빌드 출력 목록에서 제외한다.

새 검사는 v1.9.13 바이너리에서 전용 MCP 설정 진입점 부재를 재현한 뒤 수정본에서 통과했다.
별도 프로세스의 숨겨진 합성 폼으로 중복 생성 방지·기존 창 활성화·종료·재열기를 확인했다.
일반 사용자의 두 관리자 진입점은 설정/폼 생성 전에 거부됐다.
합성 Label의 GDI 렌더링 결과에서 모니터 기호와 상태 점이 정상 표시됨을 직접 확인했다.

운영 설정·서비스·사용자 화면을 시험 목적으로 바꾸지 않았다.
실제 사용자 세션의 UAC 승인 클릭과 업데이트 설치는 자동화하지 않았다.
실제 Gemini 계정 연결은 이번 UI 수정의 검사 범위가 아니다.
