# HTTP 파일 업로드 SHA-256 오류 수정 (v1.9.8)

## 원인

웹 파일 관리자는 8MiB 초과 파일을 2MiB씩 나누어 전송한다. 기존 chunkUploadSha256은 crypto.subtle이 없으면 첫 조각을 보내기 전에 “이 브라우저는 분할 SHA-256을 지원하지 않습니다” 오류를 반환했다. 일반 HTTP 주소에서는 이 API가 제공되지 않으므로 브라우저가 최신이어도 발생한다. localhost와 HTTPS에서는 제공될 수 있다.

## 변경

- Web Crypto가 있으면 기존 네이티브 SHA-256을 사용한다.
- API가 없거나 digest 호출이 실패하면 Web MCP 파일 전송에 이미 사용하던 SHA-256 구현을 공유한다. 새 의존성은 추가하지 않는다.
- 현재 2MiB 조각만 읽고 64KiB마다 이벤트 처리를 양보한다. 파일 전체를 메모리에 적재하지 않는다.
- 서버의 SHA-256 검증, 업로드 소유권, 분할 크기, 재개와 취소 동작을 유지한다.
- 공유 모듈은 로그인된 화면의 /sha256.mjs와 인증된 파일 포털의 /files/sha256.mjs에서 제공한다. 본체 리소스와 모든 Web MCP 설치 패키지에 포함한다.

## 검증 방법

- bench/Test-Upload.ps1: multipart, 큐, 5가지 crypto 상태의 해시/재개, 실제 서버 130MiB 프록시 전송을 검사한다.
- UploadIntegrationTest.js는 Chrome의 upload.test를 격리된 루프백 서버로 연결해 실제 비보안 HTTP 컨텍스트를 만든다. crypto.subtle이 없는 것을 확인한 뒤 파일 선택, 폴더, 130MiB 전송과 응답 유실 복구를 검사한다. 운영 서비스·설정은 변경하지 않는다.
- web-mcp/test/transfers.test.mjs: 공유 해시 벡터와 HTTPS 파일 포털의 실제 브라우저 업로드를 검사한다.
- Test-SetupWebMcp.ps1 및 Test-LanWebInstall.ps1: 설치 파일과 런타임 복사 경로에 공유 모듈이 포함되는지 검사한다.

## 적용

화면을 제공하는 메인 PC를 v1.9.8로 업데이트하고 브라우저를 새로고침한다. 브릿지 업로드의 하위 PC는 분할 업로드를 지원하는 v1.9.6 이상이어야 한다. 현재 설치된 프로그램은 별도 업데이트 전까지 기존 버전으로 동작한다. 바로 전송해야 하면 기존 HTTPS 원격 접속 주소로 접속한 뒤 같은 파일을 다시 선택할 수 있다.

## 검증 결과 (2026-11-04)

- 실제 HTTP Chrome: 비보안 컨텍스트 확인, 파일·폴더 선택, 모바일 폭, 130MiB 업로드, 전체 SHA-256 일치 및 응답 유실 복구 포함 25건 통과. 대용량 전송은 격리 루프백 환경에서 약 28초였다.
- JavaScript 해시·재개 15건, 기존 큐 10건, 실제 HTTP 서버 18건 및 multipart 검사 통과.
- Web MCP 전송 12건 통과. 실제 HTTPS 브라우저 업로드·폴더 다운로드 포함.
- v1.9.8 본체와 설치 파일 빌드 완료. 본체 내장 SHA-256/업로드 모듈이 소스와 일치함을 확인했다.
- Setup 패키지 추출·모든 설치 경로의 런타임 import 및 LAN 설치 통합 검사 통과. 운영 서비스 변경 없음.
