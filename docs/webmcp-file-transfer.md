# WebMCP 파일·폴더 전송 (v1.8.13)

대상 PC에 새 Setup을 설치한 뒤 **LLM / MCP 설정 → 웹 ChatGPT / Claude 설정**에서 HTTPS를 적용합니다. **WebMCP 주소 복사**로 `https://도메인/mcp`를 복사해 로컬·외부의 MCP 클라이언트에 똑같이 등록합니다. 받는 LLM PC에 원격제어 연결기를 별도 설치하지 않습니다.

## 브라우저로 전송

1. 연결된 MCP에서 `pc_open_file_transfer`를 호출하고 나온 링크를 엽니다. 로그인한 같은 PC의 권한을 사용합니다. 링크는 5분 안에 한 번만 열 수 있으며 전송 화면은 1시간 유지됩니다.
2. 파일 또는 폴더를 선택하고 대상 PC의 허용 폴더 안 전체 경로를 입력합니다. 파일은 파일명까지, 폴더는 새 폴더 경로를 지정합니다.
3. 기존 파일 교체는 `pc_get_file_info`로 확인한 현재 SHA-256을 입력합니다. 원본 백업을 남깁니다. 기존 폴더를 통째로 덮어쓰지 않습니다.
4. 전송을 누르면 각 파일의 SHA-256 계산 → 조각 전송 → 전체 검증 → 대상 반영 순서로 실행합니다. 일시 정지나 통신 장애 후 같은 파일과 경로를 다시 선택하고 재개합니다. 같은 브라우저 탭의 전송 ID를 보존합니다.
5. 다운로드는 원격 경로와 종류를 지정하고 준비를 누릅니다. 폴더는 ZIP이 준비될 때까지 기다린 뒤 **파일 받기**를 누릅니다. 브라우저의 다운로드 관리자는 Range 요청을 지원합니다. 준비된 원본의 SHA-256은 화면에 표시됩니다.

Chrome/Edge의 폴더 선택 버튼은 빈 폴더도 포함합니다. `webkitdirectory` 방식은 파일이 있는 하위 폴더를 선택하며 빈 폴더는 브라우저가 제공하지 않을 수 있습니다. 다운로드 ZIP과 직접 MCP 폴더 업로드는 빈 폴더를 지원합니다.

## MCP에서 직접 전송

| 도구 | 용도 |
|---|---|
| `pc_begin_upload` | 파일 목록·전체 SHA-256과 크기로 임시 전송 생성. `request_id`를 보존하면 응답 유실도 복구 |
| `pc_write_upload_chunk` | 최대 256KiB 조각과 SHA-256을 확인해 기록 |
| `pc_get_transfer_status` | 받은 길이/다운로드 준비 상태 확인 |
| `pc_finish_upload` | 전체 크기·SHA-256 검사 후 반영 |
| `pc_cancel_transfer` | 해당 인증 연결 소유의 전송 임시 데이터 취소 |
| `pc_prepare_download` | 파일 해시/폴더 ZIP 준비 시작 |
| `pc_read_download_chunk` | 다운로드 조각과 조각 SHA-256 받기 |

파일 최대 4GiB, 폴더 합계 최대 8GiB·10000항목입니다. 업로드 ID는 24시간, 다운로드 준비는 1시간 유효합니다. 서버 재시작 후 업로드는 같은 인증으로 재개합니다. 다운로드 준비 중 재시작한 경우 다시 준비합니다. 완성되지 않은 업로드는 대상 경로로 노출하지 않습니다. 인증 해제·비밀번호 변경 시 기존 전송에 접근할 수 없습니다.

ChatGPT의 첨부 파일은 임의의 로컬 파일 경로를 제공하지 않습니다. 이 기기의 파일은 브라우저 선택 화면으로 보내고, 에이전트가 실제 바이트를 확보한 파일은 직접 MCP 조각 도구로 보냅니다.
