# 원격제어 브라우저 대용량 업로드 개선 (v1.9.6)

## 문제와 원인 후보

구형 웹 파일 관리자는 파일 1개당 1개의 multipart HTTP POST(/fs/put)를 사용했다. 앱 서버에서는 큰 업로드를 스트리밍했지만, 브라우저와 공개 프록시를 지나는 개별 요청 본문 자체가 100MB를 넘었다. Cloudflare Free/Pro 프록시는 개별 HTTP 요청 크기를 100MB로 제한하며 413을 반환할 수 있다. 정확히 해당 서버에서 Cloudflare가 413을 발생시켰는지는 현장 추가 확인이 필요하다. 소스에는 별도 100MB 제한 상수가 없었다.

기존 Windows 업로드 및 하위 PC 중계에는 소켓 읽기 유휴 제한 15초도 설정되어 있어, 송신이 15초 넘게 멎으면 실패할 수 있었다.

## 수정 사항

- 파일이 8MiB를 초과하면 기존 단일 POST 대신 2MiB Blob.slice 조각으로 나눠 multipart 요청을 순차 전송한다.
- HTTP 파일 전송과 화면 WebSocket을 분리하여 기존 화면 응답 속도에 영향을 최소화한다. 개별 HTTP 요청은 3MiB보다 작다.
- 인증된 /fs/upload/start, status, chunk, finish, cancel을 추가한다. X-RC-Upload: 1 헤더가 없는 요청은 거부하며 기존 웹 로그인 토큰을 URL에 전달하지 않는다.
- 서버 임시 폴더에 스트리밍 적재하고 조각 크기, 서버 오프셋, SHA-256을 검증한 다음에만 위치를 갱신한다. 한 파일 최대 16GiB.
- 로그인 세션과 서비스가 유지되면 같은 브라우저에서 같은 파일을 다시 선택해 서버 확인 위치부터 이어받는다. 진행 ID는 원격 PC, 폴더, 파일명, 크기, 수정 시각에 결합한다.
- 네트워크가 끊겼거나 응답이 유실되면 서버의 진행 위치를 조회하고 최대 5회 자동 재시도한다. 확인 없이 조각을 중복 삽입하지 않는다.
- 완료 후 서버에서 전체 파일 SHA-256을 계산하고 최종 파일을 확정한다. 같은 이름의 기존 파일은 덮어쓰지 않고 새로운 이름으로 저장한다.
- 업로드 취소 시 임시 데이터를 정리한다. 사용하지 않은 세션과 임시 데이터는 24시간 이후 청소한다. 서비스가 재시작되면 인메모리 업로드 ID는 사라질 수 있어 이어받기가 처음부터 다시 시작될 수 있다.
- 하위 PC 중계는 분할 전송용 헤더를 전달하며 유휴 읽기 타임아웃을 120초로 늘렸다. 하위 PC도 v1.9.6 업데이트 필요.
- 8MiB 이하 파일은 호환성을 위해 기존 단일 multipart 업로드 방식을 유지한다.

## 기술·보안 한계

- 작업공간 폴더는 기본 작업 위치이며 접근 제한이 아니다. Windows 실행 계정 권한이 실제 접근 기준이다.
- 비밀번호, Telegram 토큰, SSH 키는 전송이나 공개 설치 파일에 포함하지 않는다.
- 브라우저는 파일 전체를 메모리에 적재하지 않고 2MiB 조각만 SHA-256 계산한다. 서버는 디스크 임시 저장소 사용.
- Web Crypto API가 필요하므로 HTTPS 또는 localhost 신뢰 컨텍스트에서 대용량 업로드가 동작한다. 미지원 브라우저에는 오류를 표시한다.
- 설치된 서비스와 실제 파일 시스템에서 외부 터널을 통과하는 실기 검증은 별도로 수행해야 한다.

## 검증

- bench/UploadChunkHttpTest.js: 격리된 실 HTTP 경로 130MiB 업로드, 크기 제한 프록시, 응답 유실, 66MiB 후 재개, 중복 조각 거부, SHA-256 변조 거부, 파일 보존, 완료 멱등성, 취소 포함 18건 통과.
- bench/ViewerUploadTest.js: 기존 브라우저 업로드 큐·폴더 처리 10건 통과.
- bench/UploadChunkViewerTest.js: Web Crypto/XHR 모의 브라우저에서 조각 응답 유실 후 자동 복구 및 4MiB 지점부터 재개 2건 통과.
- bench/UploadTest.cs: multipart 경계, 조기 연결 해제, 안전한 파일명 테스트.
- bench/UploadIntegrationTest.js: Edge 브라우저 선택 검사는 SYSTEM 계정에서 디버깅 포트가 열리지 않아 현장 테스트 보류. 대화형 Windows 사용자에서 검증 필요.
- bench/Test-Upload.ps1: SYSTEM에서 Edge GUI 테스트는 명시적으로 건너뛰고, HTTP 및 JavaScript 큐 검증은 실행한다.

## 현장 확인

1. v1.9.6으로 원격제어 서버를 업데이트한다. 하위 PC 업로드라면 하위 PC도 업데이트한다.
2. 웹 화면을 강력 새로고침하여 새 JavaScript 업로드 모듈을 적용한다.
3. 100MB 넘는 파일을 선택하고 분할 전송 진행률·저장 완료 여부를 확인한다.
4. 접속이 끊긴 경우 같은 브라우저에서 같은 파일을 다시 선택해 서버 확인 위치부터 재개하는지 확인한다.
