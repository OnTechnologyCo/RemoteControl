# 프라이버시 화면: 물리 모니터 가리기 (v1.9.5)

## 목적과 사용

로그인된 원격제어 웹 화면 상단의 **◼ 모니터 가리기**를 누르면 원격 PC의 실제 모니터 전체를 검은색으로 덮습니다. PC의 모니터 전원을 끄는 것이 아닙니다. **◻ 화면 복구**를 누르면 원상 복구합니다.

일반 데스크톱(Default)에서만 시작할 수 있습니다. UAC 보안 데스크톱 또는 Windows 잠금 화면에서는 새로운 가림 요청을 거부합니다.

구현은 Windows 10 2004 이상 / Windows 11의 SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)를 사용합니다. 검은색 최상위 창은 모니터에 남지만, 지원되는 화면 캡처에서는 제외되어 원격 웹 뷰어의 화면과 제어를 유지합니다. GDI와 Desktop Duplication/WebRTC 영상 캡처의 동작은 Windows 업데이트, 디스플레이 드라이버, 그래픽 구성에 따라 다를 수 있습니다. **지원 여부를 확인하지 못하면 실패로 처리**하고, 화면을 가린 상태라고 표시하지 않습니다.

Windows 문서: https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity

## 복구와 안전 장치

- **원격 웹 상단 [◻ 화면 복구]**를 누르면 즉시 해제 요청을 보냅니다.
- **실제 PC 키보드 Ctrl+Alt+Shift+F12**를 누르면 긴급 해제됩니다. 이 키를 등록할 수 없으면 가리기 시작을 거부합니다.
- 해당 웹 원격제어 WebSocket이 닫히거나, 소켓이 죽거나, 제어 서버가 중지되면 자동 해제됩니다. 동일한 세션의 재접속에도 가림 상태를 자동으로 복원하지 않습니다.
- 둘 이상의 원격 사용자가 붙어 있을 때는 소유자가 아닌 연결에서 가리기 소유권을 빼앗지 못하지만, **로그인된 다른 연결에서도 해제**할 수 있습니다.
- 모니터 구성이 바뀌면 디스플레이 크기에 맞춰 다시 배치하고 캡처 제외를 확인합니다. 실패하면 모니터를 가리지 않은 안전 상태로 복원합니다.
- 실제 물리 모니터를 절전 모드로 보내거나 디스플레이 장치를 끄지 않습니다. Windows 시작 시 자동으로 가리지 않습니다.
- 프라이버시 버튼은 인증된 WebSocket 안의 고정 명령만 처리합니다. HTTP의 새 비인증 엔드포인트를 추가하지 않습니다. 주기적인 웹 지연 확인 응답에 상태를 함께 실어 불필요한 조회를 추가하지 않습니다.

## 알려진 한계

- 화면 캡처 제외는 Windows가 제공하는 **협조적인 화면 캡처 API**를 위한 것으로, 완전한 보안 경계/DRM이 아닙니다.
- 관리자 수준의 별도 캡처 장비, 특수 드라이버 또는 화면 녹화 방식은 우회할 수 있습니다. 관리자 권한의 UAC 보안 화면이나 Ctrl+Alt+Del 등 **다른 데스크톱**에는 가림 창이 보이지 않을 수 있습니다.
- 사용자가 모니터를 보지 못하게 하는 기능이지, Windows 사용자의 키보드/마우스 입력 자체를 차단하는 기능은 아닙니다.
- 가림 창이 물리 모니터에서 검게 보이면서 **원격 웹 화면에는 원래 데스크톱이 계속 보이는지**는 각 실제 PC/모니터에서 확인해야 합니다.
- 연결 오류로 자동 복구되면 PC 앞 사람에게 바탕화면이 다시 표시될 수 있습니다. 민감 작업 시 Windows 자체 화면 잠금이나 물리적 접근 통제를 병행하세요.

## 검증

운영 PC를 직접 가리지 않고 수행하는 격리 검증:

bench/Test-PrivacyScreen.ps1: 소유권, 반복 요청, 소켓 종료/서비스 중지, 핫키 이후 상태 관리 16개 및 웹 제어 5개.

bench/Test-StreamServer.ps1: 실제 소켓/프레임/입력 경로에 합성 가림 객체를 주입해 프라이버시 명령/응답과 연결 종료 복구를 포함한 22개 항목.

bench/Test-Control.ps1: 화면 전송/입력 41개 회귀.

테스트는 실제 화면을 검게 가리지 않으며, 실기 수동 검증과 동등하지 않습니다.
